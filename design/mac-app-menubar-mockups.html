Menu bar panel · review before implementation

A tally slip, not a status board.

one verdict, said once the rule is the byte view measured or absent 210 pt at its tallest

The tray panel is read in about two seconds by someone deciding whether a folder is safe to delete from a full boot volume. It is a tray readout, so it is built to stay short: the proportion rule carries the byte split, the tally line carries the counts, and anything you read rather than glance at lives one click away in the ledger.

After. The verdict is stated once, with its extent riding the same baseline instead of costing a line. One state present means the tally is suppressed entirely — it could only reprint the headline. Measures 184 pt, against 210 for the panel it replaces.

RemovedThe repeated status word, the monospace treatment of drive names, the snapshot clock, and the wordmark row — you clicked a Syncy icon to get here. The gear moved down to the action row. The DESTINATIONS heading went too: the drive glyph now does that orienting work from inside a row that already existed, so it costs no height at all. It is the same glyph on every row on purpose — it marks the subject, it does not encode the state, because the phrase beside it already names that in the ledger's own words.

The rule is the byte view, the line is the count view

A segment's width already is its byte figure, so the tally is left with counts alone — and four counts do not need four rows.

The full slip, and the tallest the panel gets — 210 pt, against 446 for the four-row version it replaces — a 53% cut. The rule stays weighted by bytes: six unchecked folders holding 1.7 tb take the width their size earns, not the width their count would. Each segment keeps a four-point floor so a small state never vanishes beside a terabyte.

verified24 folders · 6.1 tb
all destinations connected · newest evidence 2 hours ago
⚙

The settled archive — 136 pt. Only destinations that are not simply connected get a line of their own; when they all are, one line says so. It still reports rather than congratulates: no badge, no “all good”, no suggestion to delete anything.

Traded awayPer-state byte figures. The rule encodes them by width and the headline carries the total, so the exact numbers stay in the ledger window — a figure you read rather than glance at.

Silent, then stalled. No rule at all when rsync has reported no total — absent rather than a barber-pole, which would imply a measurement nobody took. After ninety seconds without a heartbeat the amber line runs, so a stalled job stops looking identical to a finished one.

Removed“Owned by the Mac app. Refresh to read newly recorded evidence.”, the last rsync itemize line, the last-engine-event age, and the standalone elapsed clock. All of it remains on the Activity pane, one click away.

Empty. An absence, reported as one. No folders means no state — the ledger does not call it unchecked, which would claim it looked at something.

Headline caseLower case throughout. The idle headline is a ledger state word; a slot that holds “unchecked” one moment should not hold “Ledger Unavailable” the next.
